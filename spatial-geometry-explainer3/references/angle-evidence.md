# 角度可见性契约：让学习者指出顶点、两条边、平面

这是一份**跨领域视觉验收契约**，不预设学科、公式或目标物体。角度数值标签、颜色、说明文字都不能代替真实几何证据。

## 1. 角度身份证

每个确实需要绘出的角 `θ` 都要记录：

| 属性 | 约束 |
|---|---|
| `id` | 在整份课程中唯一，和屏幕上的位置无关 |
| `vertex` | 同一个世界/局部测点（二维则是模型坐标中的点） |
| `rayA`, `rayB` | 两条有方向的参考向量，由本题定义，不凭图像直觉猜测 |
| `plane`, `normal` | 测角平面和法线；三维中明确是否先投影 |
| `arc`, `signConvention` | 圆弧的正方向、半径、符号意义 |
| `value` | 与真实几何同源计算，单位和取值范围清楚 |
| `renderProof` | 学生能在主体上指认哪两条真实参考边，必要时从测点引出放大窗 |

角边可以是线段、轴、杆、速度方向、场的投影方向，**不一定是物体两条实物边缘**。回答“是哪两条线”时先区分实体结构与数学参考方向。

## 2. 两条线必须从一个顶点出发

给定公共顶点 `P`、非零向量 `a,b`：

```js
const endA = add(P, scale(normalize(a), displayLength));
const endB = add(P, scale(normalize(b), displayLength));
drawWorldRay(P, endA, "rayA");
drawWorldRay(P, endB, "rayB");
drawWorldArc(P, a, b, planeNormal, theta);
```

- 角度的几何计算使用世界或一致局部坐标，**不能**从屏幕像素坐标直接伪造三维物理夹角。
- 两条射线、角弧、顶点和名称在画面上直接可辨认。可在原位旁贴标签，但不能只有标签。
- 若原对象拥有局部坐标系，先说明该角是局部还是世界角。摄像机旋转不能改变物理角的数值。
- 若 3D 投影过度缩短或弧线太小：保留原位顶点和真实参考边，切换到测角平面正视视角，或沿锚点引线提供二维辅助截面；截面注明来源、坐标和平面。
- 可以将辅助窗的角形**视觉放大**以便学习，必须显式写“角形放大示意；角值按真实数据计算”，不能让学生误以为放大窗是等比例几何。
- 原位射线必须由**同一状态源**和实际几何推导，不能另外造两条“看着差不多”的标注线。
- 当角边之间有第三分量/平面外分量时，先说明测角平面内**到底取了哪两个方向**；不能拿未经投影的总量冒充局部方向。
- 标签跟随测点投影更新，有遮挡避让，颜色加名称双编码，不用屏幕左右定义对象身份。

## 3. 数学与奇异情形

- 无符号角：`acos(clamp(dot(unit(a),unit(b)),-1,1))`。
- 有符号角：`atan2(dot(n,cross(a,b)),dot(a,b))`，其中 `n` 是相容的测角法线。
- 先将三维量按题目需要投影到测角平面，再计算该平面内角。禁止无说明地把“总向量夹角”当作“投影后的局部角”。
- 零向量没有方向：若角边模长为零，应明确“该角当前未定义”或给出题目允许的极限定义，不能硬绘一个弧形。
- 参数为零、反号或角跨越 ±180° 时，先检查约定区间、方向与弧线的连续性。

## 4. 无旁白可读性测试（阻断项）

对实际运行的图像或浏览器画面逐项判断：

1. 能直接指出同一个顶点及其所属对象？
2. 能在顶点指认第一条**真实参考射线**，报出名称与来源？
3. 能指出第二条射线，解释为什么它出现在这里？
4. 两条射线确实属于指定的测角平面？弧线按正确正方向绘制？
5. 若存在放大图，能从它反查原位，并看到放大倍数/说明？
6. 在换视角、参数归零/反向和移动端下，符号与来源是否保持一致？

有关键项为 No，不要宣称“角已经清楚标注”。应优先修复几何/遮挡/显示，而不是只增加解释段落。

## 5. 视觉建议（非强制固定尺寸）

- 使用不同线型/颜色并附 ID；可调整辅助射线显示长度，但不要改变其计算方向。
- 当真实角很小、弧线投影不易辨认时，允许添加与原位相连的局部正视放大。
- 放大窗字号/宽度根据桌面和移动屏幕自适应；不能挤在主体上遮住关键几何。
- 检查主体旋转一圈及重置后，标注不会漂浮到错误对象上。
