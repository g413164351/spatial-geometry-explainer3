# 3D 相机与拖动：手感和几何真实性的双重检查

这是视角控制规范，不代表必须替换用户已有且正确的交互库。相机必须是**观察变化**而非对象真实旋转；它绝不能改变物理量、来源账本和几何角度。

## 1. 相机基底统一约定

令相机位置 `C`、目标点 `T`、世界向上单位向量 `worldUp`：

```js
const forward = normalize(sub(T, C));       // 相机看向目标
let right = cross(forward, worldUp);        // 屏幕右（右手约定）
if (length(right) < eps) {
  // 与世界向上近乎平行：使用上一帧稳定朝右向量或四元数轨迹球
}
right = normalize(right);
const up = normalize(cross(right, forward)); // 屏幕上
```

**不能**前后不统一地把 `cross(right,forward)` 写成 `cross(forward,right)`，也不能把 `camera→target` 和 `target→camera` 的方向混用。检查“世界向上”在非极点初始视角必须映射到屏幕上方。

## 2. 鼠标/触摸拖动

- 指定操作语义：如左键拖动旋转观察、滚轮缩放、复位回固定相机；可选右键/双指平移。
- 水平和垂直拖动方向必须**实际观察模型特征点**验证，不能仅看 `az += dx` 的符号。
- 连续旋转不得用 `clamp(yaw,-2π,2π)` 强行卡死。若用欧拉轨道相机，说明接近极点的限制，避免极点基底奇异；若用户要求真正全向翻滚，优先使用轨迹球/四元数而不是单纯放宽 pitch 范围。
- 鼠标 `pointerdown` 时正确 capture，`pointerup/pointercancel/lostpointercapture` 释放；如 touch-action 禁止手势滚动，应保留可用的触控交互。
- 缩放有合理边界但不能导致主体永久丢失；复位应恢复 `target/pivot/zoom/orientation`。
- 转动中标签若是屏幕空间覆盖层，其锚点每帧必须重新由对应**世界点**投影得到，不可一开始定位之后固定死在画布上。
- 不要依赖 CSS 旋转二维画面冒充用户要求的真实三维几何。

## 3. 六个观察检查

1. 默认视角下主体参考轴朝向、对象 A/B 标注正确。
2. 向右拖一下，模型特征点运动与选择的操作语义一致；向左拖回可复位。
3. 向上/向下拖，模型随视角产生连续变化，不突然倒置或镜像。
4. 连续水平转满两圈，不遇到人造硬停。
5. 俯视、侧视、斜视和复位时，测点、角度和对象身份的世界对应关系不变。
6. 角度严重透视缩短时提供与测点相连的清晰剖面，不以“模型本身已经有角”作为可读证明。

截图及手感判断必须由真实浏览器完成。自动化只能检查事件/坐标是否变化，无法独立证明用户觉得拖动自然。
