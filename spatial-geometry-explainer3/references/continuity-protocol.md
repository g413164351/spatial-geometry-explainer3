# 连续性协议：每个图形量都要能追到源头

## 1. 从一次真实失败中提炼的硬性原则

以下问题必须作为设计缺陷处理，而不是让使用者自己想象：

| 观察到的问题 | 真正原因 | 必须采取的修复 |
|---|---|---|
| “我还不知道 v 是什么，怎么就有 |v|sinθ 了？” | 没有先说明基本符号与测角参考 | 先展示总量及单位/方向，再展示两条角边和角弧，最后给出分量公式 |
| “相邻步骤之间没有联系” | 每步换视图或重新画箭头，来源断开 | 前一步的量继续可见；若换坐标/位置，先播连续变换或保留幽灵连接线 |
| “投影到不同目标看不清” | 从全局分量直接跳到局部投影 | 单设桥接步：展示输入量是否能复制；若是数学自由向量，保持方向和长度并沿轨迹移到目标 |
| “你画的一大坨” | 主体尺度极小、标签覆盖主体、没有屏幕空间布局 | 修正相机、裁切与留白；单步只突出必要元素；标签错位与局部放大 |
| “方向相反是凭感觉说的” | 没有画当地坐标轴/单位法线/直角关系 | 在每个目标处画局部切向+法向、投影垂线和闭合直角三角形，正负用点积 |
| “动完后不知道它是否还是同一根” | 复制过程改变箭头长度、颜色或朝向 | 固定 ID、颜色、向量值，用平移移动**起点**并用 `tip=tail+vector` 重建终点 |
| “对数学有验证，画面却是错的” | 只测代码，没有检查视频帧与手机渲染 | 浏览器截图 0/25/50/75/100%；测试尺寸、方向、标签、端点、身份 |

## 2. 量的来源账本（vector provenance ledger）

在动笔画图之前，至少整理以下结构（可用文本表或 JSON）：

```text
ID  u           类型: 数学自由向量
    定义:       世界系中的二维/三维输入，单位按题目定义
    表现:       蓝色，源锚点 P0，tail=P0，tip=P0+u

ID  u_A         来源: u
    运算:       在同一世界系中平移一个教学副本到 A
    不变量:     components, length, direction, unit

ID  n_A         来源: 目标 A 的局部坐标变换
    运算:       将 A 的局部单位方向转换到世界坐标

ID  u_parallel_A   来源: u_A 与 n_A
    运算:       (u_A·n_A)n_A

ID  u_residual_A   来源: u_A 与 u_parallel_A
    运算:       u_A-u_parallel_A
    校验:       u_parallel_A + u_residual_A = u_A

ID  u_B         来源: u
    运算:       在同一世界系中平移一个教学副本到 B

ID  n_B         来源: 目标 B 的局部坐标变换
    运算:       B 各自的局部轴；不可暗中与 n_A 合并

ID  u_parallel_B   来源: u_B 与 n_B
    运算:       (u_B·n_B)n_B
```

*如果两个目标的局部轴不同，必须分别用 `n_A`、`n_B` 计算；原输入 `u` 不必改变。若现实物理量无法自由搬动，这里的副本必须明确仅用于数学展示，不代表物理系统不变。*

账本中每个量至少有 `id, source, operation, frame, unit, value, anchor, displayedName`。角度另外有 `rayA, rayB, plane, signedAxis`。不同领域换名称和公式，但这个账本约束不变。

## 3. “相邻步骤交接表”

为每个相邻步骤填写（当步骤是一个过渡动画时也要填写）：

| 项 | 必答问题 |
|---|---|
| 已知 | 前一步已经看得到哪根量？其 ID 是什么？ |
| 保留 | 这一步继续显示它哪一部分？位置不变还是提供幽灵轮廓？ |
| 新动作 | 现在**做什么运算**？是坐标变换/分解/纯平移/投影/相加吗？ |
| 中间帧 | 0%、25%、50%、75%、100% 时都能定位源、目标及对应关系吗？ |
| 几何证据 | 哪根参考轴、哪个平面、哪个角弧、哪条直角边能证明公式？ |
| 学员解释 | 学员能用一句话回答“这一根来自上一根的什么操作”吗？ |

缺一项则加桥接阶段，**不能用长文字填补画面中的断层**。

## 4. 五种不同变化，切勿画成同一种

1. **分量分解** `v = v_1 + v_2`：同一参考系下两根分量首尾相接构成闭合三角形；标出法线/直角；原向量不变。
2. **纯平移/箭头副本** `p(t)=mix(p0,p1,t); tip(t)=p(t)+v`：仅改变绘图锚点，矢量值与方向不变。原位置保留低透明度幽灵与细连接路径。复制会增加“表现数量”，但不会产生新的物理速度场。
3. **把矢量投影到方向/平面** `v_n=(v·n)n`，`v_t=v-v_n`：目标法线 `n` 必须在目标位置，端点必须满足向量求和；`v·n<0` 时法向结果要**反向**，不得只画绝对值。画沿面与法向的直角标记。
4. **坐标表达变换** `v_B=R_{BA}v_A`：如果只有坐标基变，物理箭头方向不改变；画出新旧坐标系和对应的分量。若对象真的旋转则对相应实体、局部法线和附属量施加相同刚体变换。
5. **合成/传播** `r=v_1+v_2` 或链式规则：画出各输入到输出的连续连接，公式按动画时间依次显露，不要先给结果再突然补过程。

**物理语义提醒：** 自由矢量（例如空间中的数学自由向量）允许移到不同锚点用于数学比较；**有作用点的力**不能未经说明就从 A 移到 B 还声称力学系统不变（力矩可能改变）；非均匀场中不同测点的物理值未必相等。若复制仅用于“比较同一输入方向在两种几何上产生的投影”，须标记为教学复制/假设均匀输入。

## 5. 不要靠变换画面逃避解释

- 改变相机不能改变 `v`、角度、坐标轴数据；仅改变它们的屏幕投影。
- 若需要从俯视变到正视，用平滑相机过渡，阶段中始终保留一项锚定的原图元素；镜头转完才展开局部投影。
- 如果同一个对象有两个观察方向，一定显示“从哪里看”，不以图片左右推断真实左右。
- 降低杂乱的方法：淡化非重点、抽出可溯源的局部放大窗、标签碰撞避让、将公式旁移；**不是**忽然隐藏真实对象并把另一个没有线索的图当作“第 4 步”。

## 6. 连贯性判分（交付前硬门槛）

对每一个相邻步骤，分别打 Yes/No：

1. 来源箭头仍可认？
2. 新元素明确来自哪一个旧元素？
3. 操作的数学意义与动画动作相符？
4. 关键角/轴/法线出现在正确位置？
5. 中间动画帧箭头未伸缩、翻向或脱离锚点？
6. 学员只看当前两屏就能解释这一步？

任何关键项为 No 就**不能交付为已完成**。零值与反向实验是附加验收，不能替代步骤交接。


## 7. 补强：上一步“保留”必须指画面中的对象而非文本

若相邻步骤是“在目标 A 计算 → 在目标 B 计算”：

- A 的原有量保持相同 `id`、`anchor`、`vector`、方向色标和来源；即使淡化也应可追认。
- 新量的 `id` 必须是可追溯的B 的运算结果，不能覆写右侧对象在数据结构中的条目。
- 进入下一步之前自动检查 **状态索引 ↔ 可见步骤标题 ↔ 对象集合** 的一一对应。
- 截图对照要核对“哪些像素位置的实体保持、哪些由动画渐入”，不是仅对比两个不同时间的公式字符串。
- 角的两根参考射线和测角平面需加入来源账本，不能只登记标量角的 `value`。

执行方法见 `references/angle-evidence.md` 和 `references/verification-workflow.md`。
