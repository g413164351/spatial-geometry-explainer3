# 质量门槛：数学正确、步骤连贯、画面可辨认

下面的所有要求须按**当前题目**决定，不以任何既有案例的变量、图形或步骤数替代独立分析。先读 `continuity-protocol.md` 和 `angle-evidence.md`。

## A. 量与几何（阻断项）

- [ ] 每个首次出现的符号有名称、标量/矢量类型、单位、坐标系、方向/正号及来源。
- [ ] 每个实际需要的角有同一顶点、两条真实参考射线、测角平面、角弧、符号规则。
- [ ] 同一数据状态驱动公式、3D/2D 几何、标签、动画；不存在人工拼凑“看着差不多”的角或向量。
- [ ] 向量分解有点积定义、符号与重构检验；负投影箭头朝向正确，而不是只标长度绝对值。
- [ ] 区分数学自由向量、真实作用于物体的量、非均匀场；位置迁移不能偷偷改变物理语义。
- [ ] 几何推导与额外物理响应模型分开；模型近似和适用域有说明。
- [ ] 数值测试包含零值、反号、正交、平行、相同基底、边界及可预期奇异情况。

## B. 相邻步骤（阻断项）

- [ ] 为每对 `i→i+1` 写出 `retained/introduced/source/operation`；不凭空出现新元素。
- [ ] **画面**真正保留前一步的关键对象，而不仅在文案中提到它。
- [ ] 如果执行纯平移复制，五个关键帧始终保持原向量长度、朝向、单位、ID，不伪造新物理场。
- [ ] 如果执行旋转、坐标换基、镜头运动，要明确三者的不同变换规则。
- [ ] 如果目标 A → 目标 B 是同一输入的对照，第二目标出现时第一个目标的原位证据仍可追认。
- [ ] 每段进度可以倒拖、暂停；0/25/50/75/100% 帧能指出源和目标。

## C. 画面与交互（阻断项）

- [ ] 初始主体足够大且完整，元素没有因缩放过小而失去辨认性。
- [ ] 角弧、射线、向量端点、引线、标签不互相压住；屏幕空间避让真实有效。
- [ ] 辅助放大框注明来源测点、截面平面、比例或“角形放大示意”，能返回原位。
- [ ] 旋转视角、俯视、侧视、复位后，物体 ID 与公式项仍对应；相机不改变世界数值。
- [ ] 桌面约 1280×800 和手机约 390×844 无关键标签、主体部件或控件裁切。
- [ ] 拖动方向和操控符合约定，滚轮缩放、触屏与复位稳定。
- [ ] 颜色附带名称/形状编码；减少动画模式中依然可逐步查看。

## D. 实际验收（严格区分结果来源）

1. 静态离线检查：`scripts/check_offline_html.py`（只查资源依赖）。
2. 结构检查：`scripts/validate_continuity.py`、`scripts/validate_visual_contract.py`（只证明计划结构）。
3. 数学独立测试：用另一种实现或数值反例交叉检查，测试零值与符号。
4. 浏览器真渲染：桌面、手机、关键帧、旋转视角、交互触发/重置。
5. 无旁白学习测试：让人直接指出输入、角顶点、两条真实射线、各步骤新量来源和相邻步骤交接。

任何阻断项 FAIL 不得宣称完整交付；未运行的检查明确写 NOT RUN。浏览器截图工具生成成功不等于教学内容通过。

## E. 新增自动验收模板（非某个学科标准答案）

`assets/example-visual-contract.json` 是**领域无关**的视觉规格示例。默认只验证结构；严格模式要求人工复核记录与真实截图证据：

```bash
python scripts/validate_visual_contract.py assets/example-visual-contract.json
python scripts/validate_visual_contract.py assets/example-visual-contract.json --require-reviewed
```

示例的 `review_status` 刻意标记为 `pending`，因此第二条应返回失败。这是防止“未审核便宣称通过”的设计。

**视觉阅读检查：** 能在真实画面指出角的原位顶点与两条边；能比较相邻步骤保留与新增内容；能从辅助窗反查主体上的测点。无法做到就需修改画面，而不是增加冗长说明。
